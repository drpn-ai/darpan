# Technical Changelog For Darpan 3.3.0

Curated from the compare ranges on 2026-11-18. Counts exclude the release-metadata commits made at the cut.

## Versioning decision

- Minor. 33 facade-contract methods added (29 `admin.*`, 4 `facade.*`), none removed; the committed `methods.txt` goes
  from 268 to 301 lines; `x-darpan-contract-version` stays 4 (`check_contract_compat.py` 3.2.1 -> 3.3.0: compatible).
  New entities and fields are additive.
- darpan-agent re-cut at a minor version, v0.4.0 (new tables, 33 settings-catalog keys, admin services); it pairs
  with darpan 3.3.0 in both directions. darpan-hotwax, shopify-darpan, netsuite-darpan, database-darpan and moqui-gql
  have no commits and keep their tags.
- darpan-ui v4.3.0 (minor: new pages and flows, contract copy at 3.3.0).

## Backend (darpan)

### Added

- Email copy as data (DAR-BE-303): entity `darpan.email.EmailCopyBlock` (default text from `EmailCopySeedData.xml`,
  `copyText` = the production edit, empty = default); the 12 email screens keep the layout and read their words
  through the copy helper; `${var}` limited to the default's variables; any render problem uses the default;
  subjects editable through a SECA, plain text with `${name}` slots only, previewed without the template engine;
  code-built subjects are copy blocks (`subject.before`, `subject.after`, `subject.run`); no markup and no web or
  email address on any path; an edit equal to the default stores no edit; `admin.EmailAdminServices`
  `get#EmailTemplates`, `get#EmailTemplate`, `preview#EmailTemplate`, `update#EmailTemplate`, `reset#EmailTemplate`.
- Plain-text email parts (DAR-BE-315): the text part of each email is built from its copy blocks instead of the
  screen's text render, which cut each line at 132 columns and left `fail-widgets` branches empty; the text goldens
  are re-made.
- Settings store (DAR-BE-304): `darpan.config.DarpanSetting` and `DarpanSettings` (row, then `-D` property, then
  catalog default; bad values skipped; 30 s snapshot expired after commit; catalog read through its own class loader
  from each component's `darpan/settings-catalog.json`); run admission, retries and backoff, window ceiling, extract
  switches, six run-health thresholds (run health and the reaper read one set), the two-factor reminder cadence;
  `admin.SettingAdminServices` `get#Settings`, `get#Setting`, `update#Setting`, `reset#Setting`.
- Jobs as data (DAR-BE-305): `ServiceJob` gains `defaultCronExpression`, `defaultPaused`, `minIntervalMinutes`,
  `resumePreviewService`, `editedByUserId`, `editedDate`; `ServiceJobParameter` gains `defaultValue`,
  `editedByUserId`, `editedDate`; job seeds write defaults only; `data/zzScheduleJobDefaultsApply.xml` (sorts after
  every other data file, `upgrade-data.xml` included) calls `apply#JobDefaults` for jobs nobody edited; the seed guard
  is an allow-list over every loaded type; `admin.ScheduleAdminServices` `get#ServiceJobs`, `preview#JobSchedule`,
  `update#ServiceJob`, `reset#ServiceJob` (job logic in XML actions).
- Retention as data (DAR-BE-306): `darpan.retention.TenantRetentionPeriod` (tenant, table key, days; empty =
  forever); the four retention periods, the batch size and the two purge periods are settings;
  `admin.RetentionAdminServices` `get#RetentionPeriods`, `update#RetentionPeriods`; migration
  `RETIRED_JOB_PARAMETERS` (`retention.RetentionMigrations.move#PurgeJobRetentionParameters`, sequence 130, dry run
  supported) in `MigrationRegistrySeedData.xml`.
- Mascot content (DAR-BE-313): `darpan.content` entities `AppContentEntry`, `AppContentSeed`, `AppRoute`,
  `AppRouteAnchor`; `AppContentSeedData.xml` generated by darpan-ui (seed mark `87a4819f84fdffa7`);
  `facade.AppContentFacadeServices.get#AppContent`; `admin.AppContentAdminServices` `list#AppContent`,
  `get#AppContentVocabulary`, `create#AppContentEntry`, `update#AppContentEntry`, `reset#AppContentEntry`,
  `delete#AppContentEntry`; closed vocabulary, voice, length and markup rules, the bundle's 30 regexes checked
  server-side, stale-seed check.
- Notification routes (DAR-UI-123): `facade.SettingsFacadeServices.get#NotificationRoutes`, `set#NotificationRoute`,
  `send#ChatSpaceTest` as XML actions with explicit `companyUserGroupId` conditions, no new `disableAuthz` site.
- Agent config wiring (DAR-BE-307): `ApiContractGenerator.SERVICE_DIRS` gains `../darpan-agent/service/admin`; the
  eight `admin.AgentConfigAdminServices` methods are admin-app only in the CLI allowlist; `AgentTenantCap` is
  excluded from the tenant filter like `TenantRetentionPeriod`; `DarpanSettings.AREA_ORDER` lists the "Agent · *"
  sub-areas and `describeAll` sorts by area.

### Changed

- The reminder cadence, run admission, retries, run health and the reaper read `DarpanSettings` instead of
  `System.getProperty` or static constants. Run admission reads its limits before taking its lock.
- Job seeds no longer seed `retentionDays` or `staleMinutes` parameters; the purge services read their settings.
- Docs literals for moved defaults removed (runtime baseline, automation doc).

## Agent (darpan-agent)

- DAR-BE-304: settings-catalog entries `turnsPerUserPerHour`, `dailyUsdCapPerTenant`; eval caps fail fast outside the
  catalog range.
- DAR-BE-307: 31 more catalog keys ("Agent · Router", "Investigator", "Author", "Writers", "Gateway") read once per
  turn through `AgentLimits`; `AgentConfigEntities.xml` (`AgentPrompt`, `AgentPromptVersion`, `AgentRoleConfig`,
  `AgentModelPrice`, `AgentTenantCap`, `AgentText`) over shipped defaults (`AgentConfigDefaults`,
  `AgentTextDefaults`, the classpath prompts); `AgentConfig` immutable 30 s snapshot; each turn runs on one config and
  one limits read; an unpriced role refuses the turn and an unpriced response is charged at the dearest price; a
  model change re-runs the preflight on the next turn; the paid eval always runs on shipped config; the author-model
  JVM properties are removed; writers and the gateway take model and prompt from the config;
  `admin.AgentConfigAdminServices` `get#AgentConfig`, `get#AgentPrompt`, `update#AgentPrompt`,
  `update#AgentRoleModel`, `update#AgentModelPrice`, `update#AgentText`, `update#AgentTenantDailyCap`,
  `reset#AgentConfigItem`; README documents the editing.

## UI (darpan-ui, v4.2.0..ba4032c)

- Mascot content from the server (DAR-BE-313): hints with stable ids, seed generator and `mascot:seed:check`, edits and
  admin entries read once per tab behind the bundle, hidden terms stay silent.
- Contract copy for the new admin and facade methods (DAR-BE-302 wording, 303, 304, 305, 306, 307, 313, DAR-UI-123).
- DAR-UI-120 username-first sign-in (the standalone passkey button is gone; passkeys in the username autofill);
  DAR-UI-121 User Settings profile first; DAR-UI-122 Tenant Settings as rows; DAR-UI-123 Notifications grid and Add
  space flow (the Slack callback lands on Notifications); DAR-UI-124 Scripts list and per-script pages; DAR-UI-125
  Config history by day; DAR-UI-126 `StaticRecordTitle` and `StaticFactStrip`; DAR-UI-127 Audit settings static
  page; DAR-UI-128 Ruleset manager on the shared header with conclusions in popups; DAR-UI-129 edit buttons are
  icons, guarded by `editButtonsAreIcons.spec.ts`; DAR-UI-131 the mascot drags anywhere for the tab and a reload
  sends her home.

## darpan-admin-ui (CLI and admin app, `main`)

- Emails page and `emails`/`email` commands (303); Settings page and `settings`/`setting` commands (304); Schedule
  Jobs section, Retention section, `jobs`/`job`/`retention` commands (305, 306); Mascot words page and CLI (313);
  Agent pages, `agent config` commands and the Settings sub-area order (307).
- Contract copies for each of the above. The copy does not carry DAR-UI-123's three `facade.SettingsFacadeServices`
  methods, which the admin app does not call.

## Data and configuration

- Seed files changed: `EmailCopySeedData.xml` (new), `AppContentSeedData.xml` (new), `MigrationRegistrySeedData.xml`
  (+1 row), `zzScheduleJobDefaultsApply.xml` (new), and default-only job rows in `AuditSeedData.xml`,
  `ReconciliationJobSeedData.xml`, `ScriptJobSeedData.xml`, `TenantConfigSeedData.xml`, `TwoFactorSeedData.xml`.
- `data/upgrade-data.xml`: 1,948 generated records (`upgrade-data-review.md`).
- Release tooling (darpan-workflows): `release_preflight.py` keys `contentKind`, `contentKey` and `routeName` into a
  record's identity, so the mascot seed's rows no longer collapse (500 entries and 1,289 anchors had come out as 69
  and 813).
- docker-config `docker/prod/Dockerfile`: `DARPAN_REF` v3.3.0 and `DARPAN_AGENT_REF` v0.4.0; the other pins stay.
